What it is

Every Desktop Space gets its own live theme

Swipe from one Space to the next and you swipe from a quasar to a night beach to a marbling bath. A theme is a single source file: a Metal kernel that answers “what colour is this pixel?” on the GPU, or a Zig file that runs on the CPU through a tiny SDK.

Drop a file on a Space from the menu bar and Argus compiles it on the spot; save an edit and it reloads within a second. There is no engine to learn and no asset pipeline: you get a pixel grid, a clock and a frame budget. Argus runs at 30 FPS by default, draws only the Spaces you can see, and draws nothing while a full-screen app, the lock screen or a sleeping display covers them.

Themes are native code: a Zig theme becomes a dynamic library inside Argus. Only run themes you trust.

Install

One line on macOS, from source on Linux

macOS

Apple silicon
curl -fsSL https://raw.githubusercontent.com/gke0op/argus/main/install.sh | sh

It downloads the latest release, checks it against the release’s SHA-256, puts it in ~/Applications/Argus and opens it. Run it again to update. No Zig needed: every theme ships precompiled. The app isn’t notarized; the script is short, read it first if you like, or follow the zip steps.

Then click the eye in the menu bar and drop a theme on any Space.

Linux

experimental · X11
sudo apt install git make curl
git clone https://github.com/gke0op/argus.git && cd argus
make zig                              # the pinned Zig 0.17.0, into .toolchain/
make linux THEME=themes/Cygnus_A.zig  # or THEME=themes/cpu/Tutorial_Tides.zig
./argus-linux                         # Ctrl+C or kill to stop

A single static binary, pure Zig with no libc and no X libraries, that draws one theme (chosen at build time) as your X11 desktop background. Tested on Ubuntu 24.04: arm64 with Xorg/Xfce and GNOME on Wayland through Xwayland; x86_64 (emulated) with Xorg/Xfce. Zig themes run as they are; Metal themes need a CPU port first, and so far one exists (Tutorial Tides).

github.com/gke0op/argus MIT licence. Build from source on a Mac: make zig && make run.

How it works

One file per theme, three ways to run it here

.metal · .zig

Themes are single files

A .metal theme is a compute kernel over every pixel, with an optional state texture that persists between frames. A .zig theme is a State with init, step and draw: one allocation at init, none after. The Mac app compiles either on drop; the headless harness checks and times it.

GPU

Metal → WGSL on WebGPU

Each of the nine Metal themes has a one-to-one WGSL translation, run with the app’s frame semantics (30 Hz logic tick, state textures, data files). Against the Metal harness’s frame 120 at 1920×1200, every pixel is within 3/255 of Metal’s, and six of the nine within 1/255.

CPU

Zig → wasm on Workers

Zig themes compile unchanged to wasm32 with SIMD128 (Tides is 19 KB). Kernel themes split rows across Worker threads on shared memory. The 8 gates are the native harness’s own code compiled into the same module, and Tides’ final frame is bit-identical to the native one.

Cygnus A

Kerr light paths, checked

The black hole’s Metal kernels are ported to WGSL kernel for kernel, and the theme’s own Zig (tables, exposure, each frame’s step) runs as a 79 KB wasm module. On the same frame as the app, 99.996% of pixels are identical and none differs by more than 2 levels. The traced edge of the shadow matches Bardeen’s analytic curve to 1.79e-5 M (worst of 766 points).

In the app, every checked physics claim about Cygnus A is a record in a test ledger (claim, reference, measured value, bounds, the command that produced it): 49 claims, all passing. What is computed and what is chosen.

Limits

What this page can’t match yet

At full Retina size and 120 Hz, Lizard Island, Roulette Chrome and Night Tide come close to the 8.33 ms frame budget and drop some frames; their simulations stay on the 30 Hz tick, so motion is unaffected. Tides in wasm takes 17–18 ms a frame in Chrome against 15.3 ms natively, so in a browser it fails Gate 8 only. Measured in Chrome 157 on an Apple M3; Safari and Firefox are not tested yet.

The readout in the corner shows this machine’s numbers: GPU and CPU milliseconds per frame, the wasm module’s size and its threads.
