2 · Grade a Zig theme

Zig is compiled ahead of time, not in this page. Compiling Zig 0.17 here would need the compiler itself built to WebAssembly; without LLVM in it, it cannot produce the ReleaseFast code the harness times. So a pasted .zig is graded natively (a pull request runs the harness on GitHub Actions and posts the verdict, or run it yourself), and a .wasm built from it runs through all 8 gates right here. One difference to know: on wasm32 a usize is 32 bits, so the leaderboard’s most common compile error (expected type 'u32', found 'usize') does not fire in a wasm build. The native harness’s Gate 1 is the verdict.

1 · The prompt

      
The GPU track, written for this page (BENCHMARK.md’s own prompt is the Zig one). The copy includes the WGSL contract from web/README.md, the prelude, and Tutorial_Tides.wgsl as a worked example.

      
Write a single WGSL theme for Argus’s WebGPU runtime, following the contract below (the prelude is prepended to your file). The entry point is `@compute @workgroup_size(8, 8) fn argus_draw(@builtin(global_invocation_id) id: vec3u)`, writing every pixel with `textureStore(argus_out, gid, vec4f(colour, 1.0))`; add `argus_init` / `argus_step` and a `// @argus state WxH` line if your simulation needs persistent state. It must pass the Argus Metal harness’s checks, as run in the browser: compiles, runs at 320x200, no NaN or Inf, more than 100 distinct pixels, at least 2,000 pixels visibly animated between frame 1 and frame 120 (dt = 1/30 s), and under 8,333 µs average GPU time per frame at 1920x1200. Simulate a real physical or mathematical system. Output ONLY the complete .wgsl source file.
